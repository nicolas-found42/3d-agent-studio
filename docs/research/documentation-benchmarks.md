# Documentation benchmarks

Four subagents examined mature projects on November 25, 2026. Each had a separate question. Their evidence came from public READMEs, upstream configuration, published documentation, or decoded assets. All four returned findings. Two Godot contributor-guide URLs blocked automated access. The Godot README and screenshot were accessible.

## GitHub Pages

PyVista Tutorial builds docs on pull requests and deploys from `main` using the official Pages artifact and deployment actions. MkDocs demonstrates a strict build on pull requests. We tested the same approach locally and found that ordinary MkDocs strict mode left 47 repository directory links unrecognized. Studio now stages the canonical files in repository-relative layout and uses explicit Markdown, media, or source-file targets. The final builder is Zensical, the maintained successor to Material for MkDocs. It checks document paths and anchors and produces a static artifact the same GitHub actions can deploy. [PyVista workflow](https://github.com/pyvista/pyvista-tutorial/blob/fa940b5a3a2aeb92ca849be0e06b307b62d004b6/.github/workflows/doc.yml) · [MkDocs workflow](https://github.com/mkdocs/mkdocs/blob/2426e7c8978535e6a636413819c79f970c7ffce1/.github/workflows/docs.yml) · [Zensical migration and compatibility](https://zensical.org/docs/compatibility/mkdocs/migration/) · [Zensical validation](https://zensical.org/docs/setup/validation/) · [GitHub Pages publishing](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

GitHub returned HTTP 404 for the Studio project site during research. Repository Pages setup and a successful GitHub Actions deployment are required before linking the live site from the README.

## Navigation and visual style

- **Astral uv** uses a grouped sidebar, an on-page outline, code copying, and a system theme toggle. At 390 px the worker opened the mobile drawer and confirmed the viewport fit. Studio adopts those navigation and reading features without duplicating platform instructions into tabs. [Pinned configuration](https://github.com/astral-sh/uv/blob/e3e7c1eacb980339352a5ad69affcd3b6c206c92/mkdocs.yml#L2-L68) · [Installation guide](https://docs.astral.sh/uv/getting-started/installation/)
- **Three.js** makes exact symbols findable across desktop and mobile. Studio keeps command and kit names in searchable reference pages. **Krita** labels what each visual is meant to show, which informs the board links in the gallery. [Three.js reference filter](https://threejs.org/docs/?q=PerspectiveCamera) · [Krita interface tour](https://docs.krita.org/en/user_manual/getting_started/navigation.html#a-tour-of-the-krita-interface)
- **Blender** gives each user-manual section a one-line scope. Its live donation overlay widened the tested mobile viewport. Studio uses short task labels and keeps the site free of floating promotions. [Blender manual](https://docs.blender.org/manual/en/4.5/#sections)

## Second design pass

Six subagents returned independent reviews. The catalogs supplied leads. Design claims came from the owning pages, source, browser captures, or deployment records.

| Research | Observed pattern and Studio decision |
| --- | --- |
| README | Sniffnet pairs a short promise and task links with one primary screenshot. HTMLHint’s manual contents overlaps its first links. Studio keeps one render and a small action row with a direct link to the docs. [Awesome README](https://github.com/matiassingers/awesome-readme) · [Sniffnet README](https://github.com/GyulyVGC/sniffnet/blob/247b75b4f82e17b0f4b969c8e35d303d9506919a/README.md#L1-L30) · [HTMLHint README](https://github.com/htmlhint/HTMLHint/blob/87766b0590a90e75d1b0faf921bdc63624251eb1/README.md#L9-L39) |
| Documentation | The Wagtail and Argo CD tutorials place prerequisites ahead of the task and show an observable result. Wagtail’s desktop reading column measured 770 px at 16 px text. Studio uses a similar article measure, clearer heading spacing, and the rendered timeline as the first-run checkpoint. [Awesome Read the Docs](https://github.com/readthedocs-examples/awesome-read-the-docs) · [Wagtail tutorial](https://docs.wagtail.org/en/stable/getting_started/tutorial.html) · [Argo CD getting started](https://argo-cd.readthedocs.io/en/stable/getting_started/#requirements) |
| AI tools | Aider puts a real demo beside its explanation on desktop and keeps both actions above the demo at 390 px. Ollama groups first actions by intent and distinguishes local execution. Studio gives the terminal and agent paths equal visibility and names the local render boundary in the opening. [Awesome Local AI](https://github.com/janhq/awesome-local-ai) · [Aider](https://aider.chat/) · [Ollama docs](https://docs.ollama.com/) |
| Plugins | Figma gives each host its own linkable installation section. VS Code checks the first tool call after registration. Studio adds a host index and a shared `studio_doctor` check while keeping the Oh My Pi and Cursor details beside their commands. [Awesome MCP Servers](https://github.com/punkpeye/awesome-mcp-servers) · [Figma installation](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/#codex) · [VS Code verification](https://code.visualstudio.com/docs/agent-customization/mcp-servers#_verify-the-first-tool-call) |
| GitHub Pages | Material separates its landing from its docs shell. Monaco’s successful GitHub Pages deployment records the commit and environment URL. Studio keeps the native docs navigation with a dedicated landing page, then checks the deployed commit and project prefix. [Awesome GitHub Pages](https://github.com/awelist/awesome-github-pages) · [GitHub Pages examples](https://github.com/collections/github-pages-examples) · [Material landing source](https://github.com/squidfunk/mkdocs-material/blob/bcc3f28764178139b4cee96b9fb0c2ccd9bf2bd2/src/overrides/home.html#L23-L103) · [Monaco Pages status](https://api.github.com/repos/microsoft/monaco-editor/deployments/8071823458/statuses) |
| Render galleries | Manim places render output beside source. Remotion shows static posters until the visitor selects an example. Three.js keeps shareable example anchors and a distinct source action. Studio pairs four actual drafts with prompt excerpts, scripts, and review evidence. Playback starts only when the visitor plays a clip. [Awesome Video as Code](https://github.com/voidforall/awesome-video-as-code) · [Manim gallery](https://docs.manim.community/en/stable/examples.html) · [Remotion showcase](https://www.remotion.dev/showcase) · [Three.js keyframes](https://threejs.org/examples/#webgl_animation_keyframes) |
